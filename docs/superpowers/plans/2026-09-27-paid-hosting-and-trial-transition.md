# Paid Hosting and Three-Day Trial Transition Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement this
> plan task by task after review of the written design and implementation plan.
> Subagent execution is optional and requires the applicable authorization.
> Track completed steps with checkboxes and record actual verification evidence.

**Goal:** Перевести AniDachi на Free только для входа в чужие комнаты и
Plus/Pro с одним трехдневным trial с картой для любого Free-аккаунта без
использованного trial, сначала на staging.

**Architecture:** Stripe управляет подписками; Web/Supabase вычисляют права;
Worker применяет права к живым комнатам; расширение отображает доступный сценарий.
Совместимые серверы и новый клиент поставляются до отдельной активации в `T`.

**Tech Stack:** Next.js, Supabase/Postgres, Stripe Checkout/Billing,
Cloudflare Workers/Durable Objects, WXT/React, shared Zod protocol.

**Spec:** [Согласованные правила и проект архитектуры](../specs/2026-09-27-paid-hosting-and-trial-design.md).

## Как вести этот план

Единая подробная сводка для владельца и разработчика:
[переход на платный хостинг и trial](../../releases/paid-hosting-trial/transition-master-plan-ru.md).
Она объединяет действующие правила, судьбу существующих пользователей, объем
работ, локальные результаты и открытые условия выпуска; старые записи ниже
сохраняют дату и границы своего checkpoint.

- Перед каждым блоком сверять актуальные Git/source, контракты и нужные для
  него сервисы. Указанные файлы и технический подход уточнять по реальному
  коду, сохраняя согласованное поведение продукта.
- После каждого блока записывать результат, команды и их итог, commit/PR,
  оставшуюся работу и ограничения доказательств. Частично выполненный пункт
  разбивать на подпункты; общую галочку ставить после всех его критериев.
- Отдельно фиксировать написанный код, локальные проверки, staging-приемку,
  production-поставку и наблюдение реальных платежей. Одна стадия не является
  доказательством другой.
- Если код или сервис требуют другого технического решения, обновлять план
  вместе с причиной, проверенным фактом и влиянием на совместимость/откат.
  Изменение согласованных продуктовых правил сначала обсуждать с владельцем.

## Global Constraints

- Trial: 3 дня / 72 часа после оформления с картой, для Plus или Pro.
- Один trial на аккаунт для обоих тарифов; отмена/смена плана не сбрасывает срок.
- Отмена продления: доступ до исходного trial end, затем Free без платежного ожидания.
- Первый платеж: максимум 2 часа от исходного trial end; отказ/требование действия
  завершают ожидание раньше; retry не продлевает его.
- Любой Free-аккаунт без использованного trial проходит один путь с картой;
  дата регистрации не влияет. Действующие платные подписки сохраняются.
- Free не создает комнаты и не записывает личную историю; входит к Plus/Pro/trial.
- После T у Free нет собственной квоты 30 минут, ее обновления по суткам или
  таймера ожидания. Доступность и вместимость просмотра определяет комната
  платного/trial-хоста. Сохраненная история доступна для чтения, Resume и удаления;
  Resume не дает права создать комнату или записывать новый прогресс.
- Старые Free-комнаты завершаются в `T` без предупреждения и переходного ожидания;
  `T` согласуется с подтвержденной публикацией новой версии в Chrome Store.
- Покупка тарифа хостом не превращает старую Free-комнату в платную и не переносит
  ее закрытие; новая комната создается с соблюдением одной активной сессии.
- В `planCode` сохраняются `free | plus | pro`; медиа-протокол ради paywall не меняется.
- Сохраняются аккаунты, история, Stripe IDs, действующие подписки и access/consent fences.
- Staging: password gate, noindex, отдельные endpoints, Stripe TEST.
- Production: тот же Chrome Store ID `gpkolofebdhfpapbbgdkdkmlmjfidgmn`.
- Workflow: `codex/* -> PR -> staging -> приемка -> promotion PR -> main`.
- Годовой план, счетчик людей, удаление согласия истории и новые платформы вне объема.

## Review Focus

1. Два checkout одновременно, потерянный ответ Stripe и брошенная сессия:
   один trial/подписка, без ошибочного расходования eligibility — задача 2.
2. Первый счет после trial: задержка, отказ карты, 3DS, нулевой счет, поздний
   или переставленный webhook не выдают лишний платный период — задача 3.
3. Старые token/reconnect/SQL wrappers не обходят запрет Free-хостинга;
   Free-гость сохраняет доступ к платному хосту — задача 4.
4. Атомарный список закрытия при активации, hibernation, потеря доставки/ACK,
   старый JWT и создание комнаты на границе `T` не оставляют обхода — задача 5.
5. Опубликованный старый клиент, новый клиент и unpacked ZIP:
   ожидаемые ошибки и совместный просмотр проверяются на артефактах — задачи 6–7.
